# Tools：可执行能力

每个工具解决一个明确的问题，可以在没有 Agent 的情况下独立调用和验证。

工具统一通过 MCP 提供给 Agent。Agent 侧使用 MCP Client，工具侧使用 MCP Server，双方通过协议交互，因此不要求使用相同的编程语言。

新增工具时，至少说明：

- **用途**：工具做什么，适用范围是什么。
- **输入与输出**：字段类型、必填项和一个完整示例。
- **失败情形**：参数错误、权限不足、外部服务异常如何反馈。
- **副作用**：是否修改文件、调用外部服务或写入外部数据。
- **运行要求**：依赖、配置项和调用方式，示例中不包含真实凭据。

核心逻辑与 MCP 接口分开。前者实现业务能力，后者声明工具名称、描述、输入 Schema，并处理协议请求和返回结果。
同一个 MCP Server 可以提供多个工具，按功能和部署需求组织，不要求每个工具单独启动一个服务。

接入时记录服务启动方式或地址、传输方式、配置项和兼容的协议版本。本地进程调用可以使用 stdio，远程服务可以使用 Streamable HTTP；具体选择在首个工具落地时确定。

协议参考：[MCP 架构说明](https://modelcontextprotocol.io/docs/learn/architecture)。
